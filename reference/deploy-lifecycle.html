Deploy lifecycle: upload → build → run → live

The single most important story in this codebase. If you can retell this, you can explain ZeroOps.

  Q["build.q

  • Handle: services/worker/internal/build/build.go — Handle() (L84)
  • Safe unzip + package.json requirement: services/worker/internal/build/unzip.go — Extract(); tests in services/worker/internal/build/unzip_test.go
  • Railpack through BuildKit (BUILDKIT_HOST=docker-container://buildkit), 10-min timeout: services/worker/internal/build/railpack.go — runRailpack()
  • Build log streaming: railpack output → store.AppendLogs() (stream 'build') → API paginates → SPA polls GET /deployments/:id/logs?after=<cursor>. No SSE; the UI polls.
  • Failure rules: checksum mismatch / bad zip = permanent (straight to MarkFailed); timeouts/network = transient → 3 attempts via retry exchange (see queue-topology).
  • Repair paths (idempotency): message redelivered while already built → just republish the run job; two workers hit "building" on the same node → bounce with same attempt count; image exists → skip rebuild.

4. Status transitions — who writes what (the invariant, visualized)

stateDiagram-v2
  [*] --> queued: API. queueDeployment()
  queued --> building: worker.ClaimBuild
  building --> built: worker.MarkBuilt (writes image_ref)
  built --> starting: worker.ClaimRun
  starting --> live: worker.MarkLive
  queued --> failed: worker.MarkFailed (permanent)
  building --> failed: permanent OR 3 strikes
  starting --> failed: probe fail/permanent
  live --> superseded: MarkLive of next deploy
  building --> queued: ReleaseClaim (transient give-up)
  starting --> built: ReleaseClaim
  failed --> [*]: user hits Redeploy

All of this lives in one file: services/worker/internal/store/store.go: ClaimBuild, MarkBuilt, ClaimRun, MarkLive, ReleaseClaim, MarkFailed. The API owns nothing past queued.

5. Stop / start / restart — the action lane

Separate table (project_actions, partial-unique so only one open action per project+type), separate queue path (run.x, key = nodeId) as services/api/src/projects/actions.service.ts — request(); handled in run.go — handleAction() / runAction(). Note stop calls route.Delete() FIRST so the URL goes down before the container dies.
