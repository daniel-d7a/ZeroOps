Mutations and invalidation

Each action has the same shape. Call the API. Then invalidate the data that the server may have changed. The UI does not use the API response as the new state because the worker finishes asynchronously.

Two UI bugs to remember

  • Confirm dialog no-op: DialogClose runs its own click handler before the parent @click. The code cleared confirmType on update:open and removed it before confirmAction could read it. The fix keeps the type until the confirm handler clears it.
  • TanStack structural sharing: a 2-second refetch of a deep-equal deployment list returns the same object reference. A watch on data stopped the log puller for the full build. The fix watches dataUpdatedAt, which changes after each successful fetch.

  • Cursor, not offset: deploy_logs.id is a bigserial. ?after= cannot skip or duplicate lines when new rows are appended.
  • Bounded DOM: the server keeps the last 2,000 lines per deployment. The client keeps the last 1,000. A chatty build cannot create tens of thousands of <p> nodes.
  • Terminal drain: a terminal status can change while more than one 500-line batch is buffered. One pull would lose the tail. The loop continues while the last batch was full, or for three ticks after the change.
  • Autoscroll watches length, not the array: push() changes the array in place. A non-deep watch on a ref does not see the change.

Why there is no store

Pinia is installed and registered, but no store exists. No client-owned domain state is worth a copy. The server is the authoritative source. TanStack Query already provides caching, deduplication, stale times, and invalidation. A store would create a second copy of project status that could disagree with the DB.

The router guard is also intentionally thin. It caches ['me'] and redirects. It is not the authorization boundary. The API is. A client-side role check only prevents the render of a page that would return 403.

What SSE will change (not built yet)

The fixed intervals exist because the worker writes state asynchronously. The browser has no push channel. FIXLIST Phase 2 plans a fanout exchange and API SSE for deployment transitions, action completions, and runtime logs. Polling stays as the fallback after an EventSource error. Thus the UI continues to work through buffered proxies and reconnect gaps.

Speaking exercise (60 seconds)

  1. “The router starts ['me'] and the CSRF token. Each tab uses TanStack Query with its own key.”
  2. “Project status polls every 2.5 seconds without a condition because the worker changes it outside the request. Deployments poll only while they are active.”
  3. “Mutations invalidate the affected keys. They do not use the response as the final state.”
  4. “Logs are a cursor stream with a capped window and a terminal drain. They are not a normal query.”
