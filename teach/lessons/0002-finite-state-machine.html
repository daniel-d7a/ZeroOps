Lesson 2: ZeroOps as a finite state machine

Win by the end: given any line in build.Handle() or handleDeploy(), you can say what state the row was in, why the next line can only ever do what it does, and where the message lands when it fails.

ZeroOps runs three state machines on top of each other. Confusing them is why people get lost:

  • Machine A — the message ladder (RabbitMQ: attempt counter, retry/dead queues)
  • Machine B — the deployment ladder (deployments.status: queued→building→built→starting→live/failed/superseded)
  • Machine C — the theatre ladder (projects.status, project_actions.status, project_databases.status)

A is about "will I be asked again?" B is about "how far did the work get?" C is about "what does the user see?"

Machine B — the deployment ladder, every edge

stateDiagram-v2
   [*] --> queued: API projects/queueDeployment
   queued --> building: ClaimBuild (worker wins)
   queued --> failed: ClaimBuild error path / permanent at checksum+unzip+railpack+MarkBuilt
   building --> built: MarkBuilt (writes image_ref)
   building --> queued: ReleaseClaim (transient give-up or claim-crash)
   building --> failed: permanent (zip/build) OR ladder exhausted
   built --> starting: ClaimRun (run-worker wins)
   built --> failed: permanent pre-claim (no image)
   starting --> live: MarkLive (one tx)
   starting --> built: ReleaseClaim (transient give-up)
   starting --> failed: replaceContainer permanent OR ladder exhausted
   live --> superseded: MarkLive of the NEXT deployment
   failed --> [*]: user clicks Redeploy (new row, source reused)
   superseded --> [*]: image kept until pruned

You can predict the API from this table: notice the API writes only queued (insert) and reads everything else. Every other edge belongs to store.go.

Machine C — projects, actions, databases

stateDiagram-v2
  direction LR
  state "projects.status" as P {

    running --> stopped: action stop → SetProjectState

  state "project_actions.status" as A {

    [*] --> provisioning: EnsureDatabaseRow
    provisioning --> ready: Provisions MarkDatabaseReady
