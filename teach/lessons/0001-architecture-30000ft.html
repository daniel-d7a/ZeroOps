Lesson 1: The platform in one view

Objective: after this lesson, you can draw the platform from memory. You can also name the file that implements each arrow.

Why the code is difficult to follow

The system is not large. It is difficult because it has three planes. The planes do not communicate directly:

  1. Decide (API, platform DB, RabbitMQ). The API records that a deployment must exist.
  2. Do (worker, Docker, BuildKit). The worker makes the deployment exist.
  3. Serve (Traefik). Traefik lets users reach the app.

Most questions about the code are questions about the plane.

Trace: what happens when you click Deploy

These calls occur in this order. Each step is one function:

  1. services/web/src/api/client.ts — api() sends POST /api/projects/:id/deployments. It includes the CSRF header.
  2. services/api/src/projects/projects.controller.ts — upload() calls DeploymentsService.uploadZip().
  3. services/api/src/projects/deployments.service.ts — queueDeployment() uses one transaction. The transaction writes deployment queued and project deploying. Then publishBuild() in services/api/src/queue/publisher.service.ts sends the message.
  4. services/worker/internal/build/build.go — Handler.Handle() claims the job, unzips the source, runs Railpack, calls MarkBuilt, and publishes the run job.
  5. services/worker/internal/run/run.go — handleDeploy() creates the network and container, runs the probe, writes the route file, and calls store.MarkLive().
  6. traefik/traefik.yml — the file provider reads /dynamic/proj-*.yml. The URL then answers.
