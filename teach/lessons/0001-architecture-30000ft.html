Lesson 1: Cold-start the whole system in your head

Win by the end: you can diagram the entire platform from memory and say, for every arrow, which file owns it.

Why you keep getting lost

Not because it's big — because it has three planes that never talk directly:

  1. Decide (api + platform-db + rabbitmq) — "this deployment should exist"
  2. Do (worker + docker + buildkit) — "make it exist"
  3. Serve (traefik) — "let people reach it"

Every "where the heck is this" moment is really "which plane am I in?"

Trace: what happens when you click "Deploy"

Follow these in order — one function each:

  1. services/web/src/api/client.ts — api() sends POST /api/projects/:id/deployments (CSRF header included)
  2. services/api/src/projects/projects.controller.ts — upload() → DeploymentsService.uploadZip()
  3. services/api/src/projects/deployments.service.ts — queueDeployment(): one tx = deployment row queued + project deploying → services/api/src/queue/publisher.service.ts — publishBuild()
  4. services/worker/internal/build/build.go — Handler.Handle(): claim → unzip → railpack → MarkBuilt → publish run
  5. services/worker/internal/run/run.go — handleDeploy(): network → container → probe → route file → store.MarkLive()
  6. traefik/traefik.yml file provider reads /dynamic/proj-*.yml → your URL answers
