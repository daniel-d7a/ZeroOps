Lesson 10: The end-to-end test suite

Objective: after this lesson, you can select one of the 18 scenarios and name the invariant it proves. You can name the files that implement the invariant, and you can add a scenario without damage to the suite.

What the suite is

The suite is black-box. It operates the running stack over HTTP as a browser does, including the console.localhost host header and CSRF. It also inspects Docker, Postgres, and RabbitMQ when a behavior is not visible from outside. It is not a unit test suite. It does not mock the platform.

The shared harness (scripts/e2e/common.sh)

HelperFunction
say, ok, bad, finishThey print one indented line for each check, count pass and fail, and return an exit code.
assert_code, assert_contains, assert_eqSmall assertions with a 240-byte body excerpt on failure.
wait_forIt calls a shell function each second until a deadline. Each asynchronous status uses it.
req, reqj, app_reqcurl wrappers that set $CODE and $BODY, keep the cookie jar, and attach CSRF.
signup, as_user, login_userCookie jars and CSRF tokens for each user. They back off on 429 for the 10/min auth throttle.
create_proj, upload, dep_is, proj_is, wait_actionThey store new ids in $NEW_PID and $NEW_DEP and poll the console API.
zip_dir, zip_slip_craftThey build fixture zips from source folders and create the hostile archive.
composeIt detects the dev overlay by inspecting the API container mounts. The same suite runs against either stack.
Isolation discipline: each file gets a unique RUN suffix for emails and slugs. Cleanup runs before the round, after each file, and on exit. Without this, a full round of net-* networks empties Docker’s default network pool (about 30 bridges).

How to run the suite

scripts/e2e.sh                      # full suite, about 10 min
scripts/e2e.sh --list               # names only
scripts/e2e.sh retry                # substring match
scripts/e2e.sh sessions quotas      # several names
scripts/e2e.sh 05-no-listen         # one file

Before you run it, the stack must be up. .env must contain the platform secrets. Docker must reach the daemon. The runner resets student networks and containers, but it force-removes all app-* and net-* objects. Do not point it at a shared host until the cleanup uses a label filter.

Read a failure

  1. code= is not the expected value: a request-level failure occurred before the worker. The causes are auth, ownership, or validation.
  2. wait_for times out: read the deployment row and the worker logs, not the UI. Use docker compose logs api worker.
  3. The status is correct but the body is wrong: check routing or the app. Inspect the route file and the container labels and network.
  4. Only a full round fails: the network address pool is empty or a container leaked. Run cleanup and retry the single file.
  5. A timing assertion fails: the retry or dead-letter behavior changed. Check MaxAttempts and the TTL in definitions.json.

Exercise: add scenario 20

Select a behavior that the suite does not cover. One example is “bulk environment apply is all-or-nothing”. Write scripts/e2e/20-bulk-env.sh:

  1. Source common.sh and call say with a plan reference.
  2. Call signup and create_proj. Upload a fixture. If necessary, call wait_for ... dep_is ... live.
  3. Send one valid key and one invalid key through PUT /api/projects/:id/env.
  4. Assert 400. List the environment variables and assert that neither key was written.
  5. Call finish.

Keep the assertions user-visible. The failure message must name what a user would see, not an internal function.
