  edge ~~~ platform ~~~ db ~~~ proj
  • edge faces the host. It contains only Traefik, web, and the API. A student app never joins it.
  • platform carries control-plane traffic: API ↔ broker ↔ worker ↔ platform DB, plus BuildKit.
  • db is the only path to the student-db admin interface. The worker is the only platform service on it.
  • net-<projectId> is created for each project by the worker. The app, Traefik, and (when necessary) student-db join it. Nothing else joins. Two projects share no network, so the isolation is structural, not a firewall policy.

Traefik: two providers, one port

ConcernConfigurationResult
Entry pointweb on :80, published as host 8080Host port 80 belongs to Apache. Each URL includes :8080.
Docker providerexposedByDefault=false, network edgeOnly services with traefik.enable=true are routed: api and web.
Console routingHost(console.localhost) && PathPrefix(/api) → api; plain host → webThe console and API share an origin, so there is no CORS. The API is never exposed on its own hostname.
File providerdirectory /dynamic, watch: trueThe worker writes student routes as YAML files after the probe passes.
Docker socketmounted read-onlyTraefik can find containers but cannot change the daemon.

Each student route file has one router and one service:

http:
  routers:
    proj-<id>:
      rule: 'Host(`<slug>.localhost`)'
      entryPoints: [web]
      service: proj-<id>
  services:
    proj-<id>:
      loadBalancer:
        servers:
          - url: http://app-<deploymentId>:3000

No student container has labels. If a student container has Traefik labels, the invariant is broken.

drizzle migration row count"]
  GATE -->|"too old"| STOP["refuse to start"]
  • migrate is a one-shot service. It uses the same image as the API and runs dist/db/migrate.js. API and worker wait for service_completed_successfully.
  • The worker also refuses to consume jobs when the platform schema is older than MIN_SCHEMA_MIGRATION (currently 6).
  • Migrations are the API’s job. All worker SQL is in internal/store.

RabbitMQ topology is declared, not created by code

rabbitmq/definitions.json is the authoritative source. The entrypoint starts the broker and waits for the application. Then it imports the definitions at runtime. A boot-time import would drop the user that the environment created. At startup, services check that the queues and exchanges exist. They stop with an error if the definitions were never imported.

Topology by domain:

  • build.x → build.q. build.retry.x → build.retry.q has a 30-second TTL and dead-letters back. build.dead.x → build.dead.q.
  • run.x → run.node-1.q. The routing key is the node id. It has a matching retry and dead pair.
  • Prefetch is per channel. Build uses 1 and run uses 4. The worker opens a separate channel for each role.

Speaking exercise (60 seconds)

  1. “Traefik is the only published port. It routes the console host to the API or web by Docker labels. It routes student hosts by files that the worker writes.”
  2. “The platform has three shared networks: edge, platform, and db. Each project gets its own net-<id>. Student containers join only that network.”
  3. “The API owns the platform schema and the uploads. The worker owns the build and run work, the Docker socket, and the route volume.”
  4. “Migrations run one time before the API and worker start. The worker refuses an old schema.”
