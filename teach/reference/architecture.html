The 30,000-ft map

ZeroOps is a Railway-like hosting platform for student projects. One user-facing flow exists: sign up → create a project → upload a Node zip → (optionally get a Postgres DB) → set env vars → get a live URL at <slug>.localhost:8080. Everything below exists to serve that flow.

The mental model in one line

The browser talks only to Traefik. The API never touches Docker. Docker is touched only by the Go worker. The worker and API share nothing but the Postgres tables and the RabbitMQ exchanges.

Why each box exists

BoxJobWhere it's defined
traefikThe only published edge. Routes console (via Docker labels) and student apps (via file provider). Gets the docker socket read-only.traefik/traefik.yml, docker-compose.yml labels, docker-compose.yml
apiControl plane: auth, projects, uploads, env vars, admin. Publishes jobs; never manipulates containers.services/api/src/main.ts → bootstrap(), services/api/src/app.module.ts
webStatic Vue SPA served by Caddy; talks to /api same-origin (no CORS by design).services/web/src/api/client.ts — api()
workerThe muscle. Role build: unzip + railpack. Role run: containers, networks, health probe, routing files.services/worker/cmd/worker/main.go — main()
buildkitBuildKit daemon; railpack runs inside it. Privileged, GC-capped at 3 GB.docker-compose.yml buildkit, buildkit/buildkitd.toml
rabbitmqJob bus. Definitions file is the source of truth for topology.rabbitmq/definitions.json
platform-dbUsers, projects, deployments, env vars, workers, logs — platform metadata only.services/api/src/db/schema.ts
student-dbStudent Postgres databases. Only the worker (run role) and the students themselves know its creds.services/worker/internal/provision/provision.go — Ensure()
migrateOne-shot drizzle migration container; must succeed before api/worker start.services/api/src/db/migrate.ts — main()

The three networks — the actual security boundary

flowchart TD
  subgraph edge

  end
  subgraph platform
    API2["api"]; RMQ(("rabbitmq")); PG[(platform-db)]; BK["buildkit"]; MIG["migrate"]; WK2["worker"]
  end
  subgraph db
    WK3["worker"]; SDB[(student-db)]
  end
  subgraph NETP["net-<projectId> — one per project"]
    APP["student containers"]; T3(("traefik attached")); SDB3[(student-db attached if wants_db)]
  end
  edge ~~~ platform
  platform ~~~ db
  db ~~~ NETP
  • edge — who's reachable from outside: traefik, api, web.
  • platform — control plane gossip: api, worker, rabbitmq, both DBs, buildkit.
  • db — only worker ↔ student-db. Student app containers join only net-<projectId>, never edge/platform/db (services/worker/internal/docker/docker.go — RunStudent(), NetworkMode).

URL routing rules (memorize these)

RequestGoes toWhy
Host=console.localhost + PathPrefix /apiapi :3000Docker label console-api in docker-compose.yml
Host=console.localhost (everything else)web (Caddy :80, SPA fallback try_files {path} /index.html)Docker label console-web; in dev overlay → Vite :5173
Host=<slug>.localhoststudent container :3000File provider — worker writes /dynamic/proj-<projectId>.yml; old deployment keeps serving until the new one is healthy
Invariant: no Traefik labels on student containers — routing is file-provider only, written by the worker after the new container passes its health probe. Keeps state in one place and makes "deploy only goes live when healthy" enforceable from a single component.
